# 预存 Agent 提示词

按需要复制一个完整代码块，填写尖括号字段后交给 Agent。未填字段不构成授权；Agent 应先做不依赖这些字段的本地检查，再询问缺失的主机、目标或范围。凭据不填写在提示词、脚本或报告中。所有路径均需在执行时核对，历史记录不能替代现场状态。

## A. 只检查备份是否可用

```text
请检查本项目某次数据备份的可用性。

项目根目录：E:\codex\CL-vision-workbench
备份对象/快照：<填写快照 ID 或资产名称>
本次允许访问的主机和精确源路径：<填写；若仅本地检查则写“仅本地”>
检查深度：<仅文档和小型元数据 / 所选归档完整 SHA-256 与格式测试>
需要检查的分片或数据范围：<全量或明确子集>

先读根 AGENTS、docs/agent/CONTEXT.md、RUNBOOK.md、BACKUP 任务卡，
再读 rebuild/data-backup/README.md、HISTORY.md、RESTORE.md。
当前路径和备份覆盖以 docs/platform/01_NAS备份与环境恢复.md 及原清单为准。

只做已授权范围内的读取，不解包、写 NAS、挂载、删除、启动 GPU 或服务。
H200 仅用 ssh H200 直连，不使用 wrs。核对实际共享和文件系统，
不能把本地空挂载目录当成 NAS。检查 manifest、完成标记、哈希清单和实际文件集合。
“仅小型元数据”模式不得擅自读完整个 805 GiB 归档，也不能据此报告全量哈希通过。

区分：本地报告记载、远端当前可读、小型元数据一致、归档完整校验通过、
实际解包恢复通过。逐项列出证据时间、已检查内容、缺失项和建议下一步。
源目录已经丢失时，不运行依赖原源目录的 verify_dataset_snapshot.py 作为恢复证明。
不要执行任何历史备份脚本，也不要据旧授权删除数据。
```

## B. 恢复并解包指定数据

```text
请把指定数据备份恢复到一个全新的目录，并完成所选范围的逐文件校验。

项目根目录：E:\codex\CL-vision-workbench
执行主机：<H200 / 其他明确主机 / 本机>
备份对象及精确源路径：<快照 ID、NAS 路径>
恢复范围：<完整 Dataset / 仅 yolo_full / 指定分片 / Gray1 train.tar / 其他明确范围>
最终目标绝对路径 RESTORE_TARGET：<尚不存在的独立目录>
执行记录目录：<数据集合之外的新目录>
本次授权：读取上述备份和校验材料；在上述恢复目标、其同级 .partial
及记录目录写入；通过全部校验后无覆盖地原子发布。无需再次询问这些已明确授权步骤。

先读根 AGENTS、CONTEXT、RUNBOOK、BACKUP 任务卡及 rebuild/data-backup/RESTORE.md。
从平台 01 和原始清单确认资产身份，不用旧文档失效路径猜测现址。
H200 仅 ssh H200 直连。未明确授权挂载时，缺失 NAS 挂载应报告缺口，不自行挂载。
若主机、数据范围或目标未填写，先做本地材料检查，取得必要信息后再写入。

执行要求：
1. 明确最终路径和父目录，拒绝越界、符号链接、重解析点、悬空链接和已有目标。
   最终目录及同级 .partial 都应不存在；它们必须在同一文件系统。
2. 检查源共享身份、权限、空间和现有任务。完整 Dataset 展开内容约 835.74 GiB，
   建议至少 1 TB 可用空间并留余量；若保留本地压缩包，还需额外空间。
3. 按所选范围校验 manifest/完成标记、归档 SHA-256 和 zstd 流；
   检查 TAR 路径与成员类型，拒绝绝对路径、.. 越界和未经审查的链接、特殊文件、重复覆盖。
4. 独立 tar.zst 分片逐片解包，不拼接成一个大包；普通 TAR 不使用 zstd/gzip。
   普通目录/模型直接按清单复制。默认不恢复其他人的 UID/GID。
5. 在新 .partial 中核对完整路径集合、普通文件数、总字节和逐文件 SHA-256，
   检查额外/缺失文件；使用明确源清单，不依赖文件数量单项判断。
   全量 Dataset 的 136579 文件/897366345935 字节仅适用于全部 32 片。
   子集由分片成员清单与 source-files.jsonl 构造预期集合，不冒充全量验收。
6. 原始源目录不可用时，按 source-files.jsonl 验恢复数据；不要把恢复目录
   传给依赖源 mtime 的旧验证器。缺少可信逐文件清单时，从已验证归档建立成员哈希，
   或报告验收未完成，不凭旧 VERIFIED 标记发布。
7. 全部通过后同文件系统无覆盖原子改名。失败保留 .partial 和失败记录，不发布、不自动清理。
8. 在数据目录之外记录快照/资产身份、源和目标、范围、开始结束时间、
   命令与工具版本、哈希结果、文件/字节数、失败重试和最终状态。

本任务不包括删除源数据、覆盖业务目录、切换服务、安装系统依赖或启动 GPU 任务。
依赖缺失时先报告所需工具与原因。已有环境能够执行则继续，不追加无依据的确认流程。
最终提供恢复目录、验收记录，以及下一步如何指向数据配置；原配置和证据不改写。
```

## C. 补收本地尚缺的备份证据

```text
请补收指定备份的小型元数据和相关执行程序，使本地资料更容易追溯。

项目根目录：E:\codex\CL-vision-workbench
对象及允许读取的远端路径：<明确快照/任务目录>
允许收集的文件：<逐项列出 manifest、SHA256SUMS、VERIFIED、日志、程序等>
本地新目标：<rebuild/data-backup/evidence/下未使用的日期目录>
单文件及总大小上限：<填写，例如 100 MiB / 500 MiB；源全集清单可能较大>

先读项目规则和 rebuild/data-backup/README.md、SOURCES.json。
仅访问明确列出的材料；先列出文件大小，超过上限或发现凭据内容时停止收录该文件并说明。
不得顺带下载数据图片、模型、镜像、大归档，不递归复制整个服务器任务目录。
H200 用 ssh H200 直连；NAS 源只读。本地写入已由本任务授权。

不覆盖现有证据。每份文件先写 .partial，独立回读 SHA-256 后原子改名；
生成包含源主机、精确路径、采集时间、字节数、源/目标哈希的独立清单。
原文件不编辑；日志如需要脱敏，应另生成明确标记的脱敏副本并记录转换，
不把脱敏结果称为原字节副本，也不保存明文密码。
程序只收录、静态核对，不执行或导入。写明它依赖原路径、源目录、工具和固定数据的限制。

仅更新本资料包的导航与版本化清单，保留以前清单和原始报告。
完成后说明收齐哪些、缺失哪些，区分“证据已下载”与“备份/恢复已重新验收”。
不要提交或推送 Git；被忽略的脚本不得用 git add -f 绕过规则。
```

原始 Dataset 的[历史专用提示词](nas-docs/01_恢复_AGENT提示词.md)保留用于溯源；开始新的恢复任务时优先使用上面的 B 模板，补充当前范围和路径。
