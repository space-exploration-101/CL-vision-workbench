# 数据恢复、解包与使用

先选择需要的数据，再填写 [Agent 提示词](PROMPTS.md)。本页是恢复方法，不表示已执行；具体资产路径、哈希和备份覆盖请核对[平台 01](../../docs/platform/01_NAS备份与环境恢复.md)及其原始清单。NAS 访问、目标位置和写入范围由本次用户任务确定。

## 1. 选对材料和空间

| 需要什么 | 找什么 | 如何恢复与使用 |
|---|---|---|
| 66,006 张原始图片和标签 | 原始 Dataset 快照内的 yolo_full 分片 | 独立 tar.zst 逐片流式解包；原图为 R-only 语义，不能直接按普通 RGB 转灰度 |
| 完整原始 Dataset | 同一快照的全部 32 个分片 | 包含其他历史子集；解包内容约 835.74 GiB，建议至少 1 TB 可用空间，另留文件系统和日志余量 |
| 已完成验证的 Gray1 训练/验证/测试集 | `datasets/train.tar` | 未压缩 TAR，包含 26,794 张数据及标签/元数据；train 名称并非仅训练划分 |
| 量化标定和快速评估 | `datasets/cal462.tar`、`datasets/eval462.tar` | 未压缩 TAR；标定包为 462 张图片，评估包另含标签和元数据 |
| 6,600 张 PT 推理结果 | `results/inference_6600.tar` | 是指标和预测输出，不是输入图片 |
| 训练、量化结果 | `results/training/`、`results/quantization/` | 普通文件目录，按清单复制和校验；量化 input_symlinks.tar 只有链接定义，真实输入另从 cal462/eval462 恢复 |
| 500 张工程测试批次 | `20261013_21类目标FPGA上板测试数据` | 普通文件目录，约 15.62 GiB；按 BACKUP_MANIFEST/哈希复制，不需要整体解压 |
| 旧 R-only 实验选择集 | 09-25 历史实验目录的选择清单、旧权重及原始 Dataset 快照 | 由 selection-manifest 定位源文件/分片；不能仅拿到 199 MB 的历史目录就认定图片也齐全 |
| 三份临时 PT 副本 | 平台 01 第 3.6 节的临时目录 | 普通文件复制；校验各模型哈希和身份，不能混用历史权重 |

只恢复子集时，先由分片计划计算所选范围的实际展开大小；不能按分片压缩体积估计目标空间。若先复制归档再解包，需要同时容纳归档和展开数据。通过 NAS 流式解包可避免本地再存一份完整压缩包，但不会减少最终数据空间。

## 2. 开始前必须确定的内容

1. 明确快照 ID、全量/子集范围、目标主机、绝对目标路径和记录目录。最终目录及同级 `<目标>.partial` 都应不存在；也要拒绝悬空链接，不能只用 `test -e` 判断。
2. H200 用 `ssh H200` 直连。Linux 核对 `findmnt` 确认真实共享为 `//10.2.26.26/902_data`、类型 CIFS；未挂载时不能把空目录当 NAS，也不自动执行挂载。
3. 核对最终路径、父目录、链接/重解析点、权限与空间。恢复到独立数据盘目录；不要在 NAS 快照内或当前业务目录内展开。
4. 读取实际 manifest 和完成标记，核对 SHA-256；压缩分片还需 `zstd -t`。校验可能读取数百 GB，应限定所选范围并记录耗时。子集任务只验收子集，不能标成全量通过。
5. 解包前检查 TAR 成员：拒绝绝对路径、`..` 越界路径和未审查的符号/硬链接、特殊文件；拒绝跨分片重复成员覆盖。源清单路径也要限制在恢复根下。

恢复不需要 GPU。当前任务未要求业务切换时，恢复完成后只交付数据与验证记录，不启动训练、服务或清理源数据。根规则和[备份任务卡](../../docs/agent/tasks/BACKUP.md)仍适用。

## 3. 原始 Dataset：独立 tar.zst 分片

固定快照为 `auto-landmark-Dataset-20260922-161828`。NAS 位置见[原始完成报告](../../docs/class-21/operations/runs/backup/raw-dataset/auto-landmark-Dataset-20260922-161828/completion-report.md)。

32 个分片是 **32 个独立 tar.zst**，不是一个大压缩包的分卷；不要先用 `cat` 合并。每个文件归属由 `shard-plan.json`、`shards.jsonl` 和 `filelists/*.nul` 确定。仅需要 yolo_full 时应按计划选 train/val/test 对应分片；历史记录为 21/3/3 个，其他五片是附属数据，实际仍须读清单确认。

执行顺序：

1. 核验所选分片及依赖清单的身份，检查成员路径和目标空间。
2. 创建新的同级 `.partial` 目录；逐片 `zstd -dc` 流式送入 tar，保留目录结构，默认不还原他人的 UID/GID。
3. 对展开后的每个文件核对相对路径、字节数和 SHA-256，同时检查缺失、额外文件及目录/链接异常。
4. 全量任务应达到 136,579 文件、897,366,345,935 内容字节；只恢复 yolo_full 或单片时，预期集合必须从源清单按所选范围构建，不能套用全量数字。
5. 所有检查通过后，在同一文件系统中以不覆盖方式原子改名为最终目录，并在数据目录之外保存验收记录，避免把日志混入受验数据集合。

完整流式命令和逐文件哈希校验代码已在[原恢复说明](nas-docs/00_恢复说明_README.md)保留。它是冻结版本：其中单分片示例只是提取示例，不能替代上述 `.partial → 子集全量验证 → 发布` 流程。执行 Agent 应补齐目标链接和 TAR 成员审查，不直接把历史代码块整段盲跑。

`verify_dataset_snapshot.py` 用于备份快照与仍存在的源目录比对，依赖源目录的 path/size/mtime。**源目录丢失后的恢复验收，应使用 source-files.jsonl 对恢复内容逐文件验哈希**，不能用恢复目录冒充原源目录，也不能仅凭该脚本的成功文本发布；分片数须独立核对三份记录相等。

## 4. 普通 TAR 与普通目录

Gray1 的 `train.tar`、`cal462.tar`、`eval462.tar`、`inference_6600.tar` 均为标准未压缩 TAR，不使用 gzip/zstd 解码。核对相邻 `.sha256` 文件后，用 `tar -tf` 检查成员；在上述门禁通过的全新 `.partial` 目录中才进行 `tar -xf`。Linux 可加 `--no-same-owner`；Windows 的 tar 选项以实际工具为准。

完整 Gray1 数据集原记录为 53,597 个普通文件；cal462 为 462，eval462 为 929，PT 结果为 6,615。TAR 的目录 member 不计入普通文件数。核对包内实际顶层目录后再决定 dataset.yaml 的目标路径；不要通过 `--strip-components` 猜测布局。

若包内有逐文件哈希清单，按其相对根验证；若没有覆盖全部内容的清单，则从已经通过归档 SHA-256 的 TAR 构建成员路径、内容哈希和大小集合，与恢复文件逐项比较。仅能证明归档哈希、不能验证展开内容时，应明确记录未完成，不能写“完整恢复通过”。

普通目录采用“读取源清单 → 复制到新 `.partial` → 回读目标全部文件 → 核对源未变 → 发布”。500 张批次用本目录 [BACKUP_MANIFEST.json](evidence/test500-20261013/BACKUP_MANIFEST.json) 和 [BACKUP_SHA256SUMS](evidence/test500-20261013/BACKUP_SHA256SUMS)辅助对照远端同名文件；这两份本地清单只描述 10-13 时点。备份额外生成的三个 `BACKUP_*` 审计文件应单列，不混入 6,077 个源数据文件验收。

临时 PT 副本按平台 01 和 NAS 实际 manifest 比较模型哈希。旧 R-only 选择集按角色清单保留重叠关系，不以文件去重擅自改变实验布局。

## 5. 解包后怎样使用

- **原始 R-only 数据**：先核对数据合同和标签语义；普通三通道转灰度会改变亮度，应按项目合同显式取 R。原始图不能直接冒充 Gray1/net1280 输入。
- **Gray1 M 数据**：保持 train/val/test 划分；为新机器另写数据配置指向恢复目录，保留原 dataset.yaml 和哈希证据不变。模型应匹配正式 50e 身份。
- **量化小集**：cal462 用于确定量化参数，eval462 用于快速回归；462 张通过不能替代 6,600 张全测试集结论。
- **500 张工程集**：区分原图、gray、net1280、cam2000 及 PT/ONNX 参考；直接 resize 和板端降采样不能默认逐像素相等。后补索引或 trace 需单独核验来源。

数据语义与版本看[输入预处理知识库](../../docs/class-21/knowledge/02_21类目标数据与输入预处理.md)。训练、推理、量化和服务启动按各自任务授权与资源门禁执行，数据解包通过只表示资产恢复通过。
