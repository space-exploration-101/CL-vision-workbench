## 2. 正式训练前的硬门禁

### 2.1 确认任务类型

M 数据集中共有 23,206 个正样本目标：

- 两个关键点彼此重合：23,206 个，占 100%；
- 两个关键点同时位于 bbox 中心：22,172 个；
- 该问题不影响图像预处理和训练程序运行，但会直接决定 Pose 指标的业务意义。

正式训练前必须书面确认以下二选一结论：

1. 两个重合关键点就是业务需要的标签语义，继续训练 Pose 模型；
2. 业务只需要类别与检测框，改用检测模型；或者重新生成两个具有不同物理意义的关键点标签。

在该结论未确认前，可以做短周期实验，不应把 150 epoch Pose 权重定义为正式交付模型。

### 2.2 固定验收目标

正式运行前需明确模型验收目标，至少包括：

- Box mAP50 和 Box mAP50-95；
- Pose mAP50 和 Pose mAP50-95；
- 21 个类别各自的最低召回率或 mAP；
- 地标类与 `moon` 是否使用同一阈值；
- FPGA 或量化后允许的精度下降范围；
- 单张图推理延迟、吞吐或资源上限。

未确定业务阈值时，本轮只能产出“训练基线”，不能宣称达到交付精度。

### 2.3 GPU 与运行环境门禁

- 必须独占一张持续空闲的 H200，不与其他用户的计算任务共享；
- 连续检查利用率、显存、计算进程、进程所有者和运行时长；
- 启动门禁为无活动计算进程、利用率不高于 20%、空闲显存不少于 32 GiB；
- 不停止或抢占其他用户任务；
- 正式训练预计持续两天以上，应先协调共享服务器使用窗口；
- 仓库 HEAD、远程 revision、镜像版本和数据集哈希必须在启动记录中冻结。

## 3. 固定训练契约

模型和数据必须同时满足：

```yaml
input: [B, 1, 1280, 1280]
ch: 1
nc: 21
kpt_shape: [2, 3]
channels: 1
input_semantics: gray1
```

V1 正式基线参数建议固定为：

| 参数 | 值 | 说明 |
|---|---:|---|
| epochs | 150 | 最大训练上限，不要求固定跑满 |
| imgsz | 1280 | FPGA 输入 ABI，不调整 |
| batch | 4 | 已通过 H200 烟测 |
| workers | 4 | 已通过数据加载烟测 |
| device | 0 | 容器内只暴露选中的一张 GPU |
| amp | true | 烟测已成功运行 |
| cache | false | 不额外占用大量主机内存 |
| multi_scale | false | 固定输入尺寸 |
| save_period | 10 | 每 10 epoch 保存周期权重 |
| patience | 30 | 验证集最优 fitness 连续 30 epoch 未改善时早停 |
| optimizer | auto | 最终实际值以 `args.yaml` 和日志为准 |

HSV、旋转、平移、缩放、剪切、透视、翻转、mosaic、mixup、copy-paste、BGR 交换和 erasing 继续保持为 0。M 数据来源本身已有离线视角变化，V1 不在训练阶段引入新的增强变量。

模型从 Gray1 YAML 结构零初始化，不加载三通道预训练权重。`args.yaml` 中 Ultralytics 的通用 `pretrained` 字段不能替代实际初始化日志；验收时必须同时看到：

```text
Initialization: from scratch
Input contract: gray1 [B,1,1280,1280]
```

## 4. 推荐执行方案

### 4.1 阶段一：正式训练实现预检

不要直接把 smoke wrapper 当作正式脚本。正式启动前应新增或审核独立的 formal wrapper，至少支持：

- `epochs=150`、`patience=30`、`save_period=10`；
- 独立运行 ID，拒绝覆盖旧目录；
- 数据集只读、输出目录可写、容器根文件系统只读；
- 使用完整 GPU UUID，只暴露一张 GPU；
- GPU 最终门禁和启动竞态检查；
- 完整 stdout/stderr、GPU 指标、开始和结束时间；
- 信号退出时保留 checkpoint 与失败现场；
- 运行状态 `WAITING|RUNNING|PASS|FAILED|STOPPED`；
- 不设置 smoke test 的 55 分钟硬超时。

正式 wrapper 需先用小型测试验证参数展开、路径、状态记录和失败处理，但不得再次启动完整训练。

### 4.2 阶段二：最大 150 epoch 的曲线驱动训练

`150` 是允许模型充分收敛的最大预算，不是必须跑满的固定轮数。该数值来自训练仓库原有的正式入口默认值和从零训练 9,919 万参数模型的保守预算，目前没有证据证明第 150 epoch 一定优于更早的 checkpoint。

推荐从零开始一次连续运行，配置 `epochs=150`、`patience=30`，由验证曲线和 early stopping 决定实际结束点。不把 20、50、80、100 epoch 拆成多个独立实验，也不在尚未验证恢复语义时依赖反复 resume。

曲线判断规则：

1. 前 20 epoch 作为最小观察窗口。除 OOM、NaN、数据错误或资源冲突外，不因短期指标波动停止；
2. Pose 业务语义确认后，以验证集 `Pose mAP50-95` 和 Ultralytics fitness 作为主要选择依据，同时观察 Box mAP50-95；
3. 使用最近 5 个 epoch 的移动趋势判断，不根据单个 epoch 的峰值或回落作决定；
4. 验证集最优 fitness 连续 30 epoch 没有改善时，由 `patience=30` 自动早停；
5. 若 train loss 持续下降，但 val loss 持续上升且 val mAP 连续 10 至 15 epoch 下降，记录过拟合告警；经明确授权后可提前停止本方任务；
6. 最终始终选择验证集意义上的 `best.pt`，不是机械选择 `last.pt`；
7. test split 不参与曲线判断、早停、阈值选择或 checkpoint 选择。

在同一次运行中设置观察点：

| 观察点 | 预计累计时间 | 处理方式 |
|---:|---:|---|
| epoch 1 | 约 21 分钟 | 确认与 smoke 性能相近，无 NaN/OOM |
| epoch 20 | 约 7 小时 | 首次趋势检查，不根据单点指标停止 |
| epoch 50 | 约 17.6 小时 | 检查移动趋势、逐类别指标和过拟合迹象 |
| epoch 80 | 约 28.2 小时 | 判断新增 epoch 是否仍带来稳定收益 |
| epoch 100 | 约 35.2 小时 | 重点检查是否已经进入平台期 |
| epoch 150 | 约 52.8 小时 | 未触发早停时达到最大训练上限 |

观察点默认只读，不因为“达到某个 epoch”自动停止。自动结束只由 `patience=30` 或最大 `epochs=150` 触发；人工停止只允许在出现本文停止条件、明确过拟合且得到授权时执行。

### 4.3 阶段三：冻结最佳权重

训练结束后：

1. 确认退出码为 0，final validation 完成；
2. 确认 `best.pt` 和 `last.pt` 存在且非空；
3. 记录两个权重的 SHA-256；
4. 保存 `args.yaml`、`results.csv`、训练曲线、混淆矩阵和完整日志；
5. 根据 val 指标选择 `best.pt`，不使用 test 调参；
6. 将选定权重和运行记录置为只读候选产物，不覆盖 smoke 权重或旧实验。

### 4.4 阶段四：独立 test 评估

模型和阈值冻结后，只运行一次独立 test 评估：

- 使用完整 test split 6,600 张；
- 输出总体和逐类别 Box/Pose 指标；
- 单独报告 20 个地标与 `moon`；
- 报告空标签误检率；
- 生成每类真阳性、假阳性和假阴性可视化；
- 保存预测结果、配置、日志与哈希。

test 结果不用于继续调参。若 test 不达标，应登记为新实验，而不是覆盖本轮结果。

### 4.5 阶段五：量化前门禁

只有正式训练和独立 test 均通过业务阈值后，才进入量化：

- 冻结模型 SHA-256 和输入 ABI；
- 选择独立标定集，不使用 test 集调节量化参数；
- 比较 PyTorch、ONNX、量化模型和 FPGA 输出；
- 记录逐阶段精度下降和性能变化。

## 5. 时间与资源预算

基于本次 H200 独占烟测：

```text
1 epoch = 1,268.19 秒
150 epochs = 190,228.5 秒 = 52.84 小时
```

曲线驱动训练的实际耗时取决于 early stopping：

| 实际结束 epoch | 预计训练时间 |
|---:|---:|
| 50 | 约 17.6 小时 |
| 80 | 约 28.2 小时 |
| 100 | 约 35.2 小时 |
| 120 | 约 42.3 小时 |
| 150 | 约 52.8 小时 |

加上首次扫描、容器启动、周期保存和最终验证，仍应按最大情况安排资源窗口：

```text
预计：由验证曲线决定，常见观察范围约 18-53 小时
最大预算：约 53 小时
计划预留：48-58 小时
调度窗口：至少连续 60 小时
```

该估算成立的前提是：同一数据集、`batch=4`、单张独占 H200、无其他任务争抢 CPU/I/O。共享 GPU 会使 ETA 失真，并可能影响双方任务。

烟测峰值显存为 36.4 GiB，H200 容量充足，但正式训练仍需持续记录峰值。建议至少预留 20 GB 输出空间，用于周期 checkpoint、最佳/末次权重、曲线、预测可视化和日志。

## 6. 训练期间监控

每 5 至 30 秒记录：

- GPU UUID、显存占用、利用率、功耗和温度；
- 训练 PID、容器 ID和运行时间；
- 当前 epoch、batch、平均 step 时间和 ETA；
- train/val loss；
- Box/Pose precision、recall、mAP50、mAP50-95；
- 输出目录大小和最近更新时间；
- NaN、CUDA OOM、数据损坏和 DataLoader 异常。

预计剩余时间使用最近 3 至 5 个完整 epoch 的中位耗时计算，不能只按第一个 batch 外推。每个观察点应输出一次机器可读快照。

## 7. 验收条件

流程验收必须全部满足：

- 数据集 `VERIFIED` 存在；现场没有早期文档曾误记的 `ACCEPTED`，完整独立 test 结果见 `21类灰度图独立test评估报告.md`；
- 输入、模型首层、类别与关键点契约一致；
- 达到最大 150 epoch，或由 `patience=30` 产生完整、可解释的 early stopping 记录；
- final validation 正常完成；
- 无 NaN、OOM、损坏图片或未解释的数据跳过；
- `best.pt`、`last.pt`、配置、指标、日志和哈希齐全；
- 独立 test 已执行且未参与调参；
- 达到训练前约定的总体和逐类别业务阈值。

若未预先约定精度阈值，只能验收为“正式训练基线完成”，不能验收为“模型精度达标”。

## 8. 停止条件

出现以下任一情况应停止本方任务并保留现场：

- GPU 被其他用户任务占用或出现不可接受的资源竞争；
- CUDA OOM、GPU 错误、持续过热或驱动异常；
- 输入张量不是 `[B,1,1280,1280]`；
- 检测到 RGB、R-only 与 Gray1 混用；
- 类别数或关键点结构不是 `nc=21`、`kpt_shape=[2,3]`；
- loss 或指标出现 NaN/Inf；
- 数据集出现损坏、标签越界或未解释的样本跳过；
- 输出空间不足；
- 仓库、镜像、配置或数据集 revision 与启动记录不一致；
- 业务确认 Pose 标签不应使用重合关键点。

停止时不得删除运行目录、checkpoint 或日志，不自动改标签来绕过问题。
