## 2. 数据方案

### 2.1 462 张标定集

只从 train split 选择：

- 21 类 × 每类 20 张正样本，共 420 张；
- 42 张空标签/背景样本；
- 合计 462 张；
- 固定 seed：`20260918-cal462-v1`；
- 每个 `group_id` 最多一张；
- 在类别和 group 约束内覆盖不同亮度、目标尺寸、位置和视角。

标定器不读取标签，但必须保存 `calibration-selection.json`，记录类别、group、空样本标志、源相对路径、已有源文件哈希和 seed。

### 2.2 462 张快速评估集

test 只有 360 个独立 group，不能同时满足“462 张”和“每 group 最多一张”。快速评估集改为：

- 21 类 × 每类 18 张正样本，共 378 张；
- 84 张空标签/背景样本，使背景占比接近完整 test；
- 合计 462 张；
- 固定 seed：`20260918-eval462-v2`；
- 先覆盖尽可能多的独立 group，再允许同 group 第二张；
- 每个 group 最多两张，不允许重复文件；
- 强制覆盖上述五个保护类别及其高误差、漏检和误检样本类型。

保存 `evaluation-selection.json`，同时报告独立 group 数、每 group 样本数分布、类别数和背景数。calibration 来自 train，evaluation 来自 test，两者不能共享文件。

### 2.3 完整 test 回归

462 张只作为快速筛查。FP16 和 QDQ 均通过快速门禁后，必须在完整 6,600 张 test 上做最终回归，使用与 PT 基线相同的 `conf`、NMS、匹配和像素误差统计口径。

### 2.4 选择工具

执行前实现并 CPU 测试任务专用工具 `prepare_pose21_quant_set.py`。该工具只读正式 manifest，确定性生成两份选择清单并真实复制选中文件；不使用软链接，不修改正式数据集。

示例接口是目标设计，不是当前已存在的 CLI：

```bash

  --dataset /data3/ywang/yolo-gray1-datasets/pose21-gray1-1280-m-v1 \
```

生成后检查：数量、split、类别、背景、group 分布、图像与标签配对、单通道 `1280×1280 uint8`、无重复文件，以及清单记录与正式 manifest 一致。

## 4. 最小量化流程

本轮只运行：

```text
输入检校
-> 同集 PT baseline
-> FP16 ONNX 导出与同集评估
-> 最小 QDQ 量化
-> QDQ ONNX 同集评估
-> 通过后完整 6,600 张回归
```

不自动运行 `fpga_test_pack`、`fpga_input_roundtrip_eval`、`generate_bin`、`merge_bin`、`bundle`、trace 或 release package。

当前正式八步 runner 会继续进入 FPGA/BIN 阶段，不适合直接用于本轮最小范围。历史任务目录中的 `quantize_minimal.py` 只证明组合方式可行，不是平台正式入口。执行前应将最小组合整理为任务内冻结工具或正式受测试入口，并记录来源和内容。

### 4.1 输入检校

在容器内运行当前正式检校器：

```bash
/opt/ywang/yolo-runtime/bin/python \
  /platform/pipeline/runner/07_validate_input.py \
  --job-dir /job --min-cali 462 --min-test 462
```

任何数量、标签、通道、尺寸或类别错误都停止后续阶段。

### 4.2 同集 PT baseline

量化平台的 PT evaluator 必须先在同一 462 张快速评估集上运行。由于完整 PT 报告使用独立像素评估脚本，还要在这 462 张上复跑相同脚本，确认平台预处理和后处理没有改变当前基线。

门禁：

- 第一层卷积为 1 通道，输入为 `[N,1,1280,1280]`；
- 输出 finite、非全零，21 类 pose ABI 正确；
- 两条 PT 评估路径的逐图类别、检测数和匹配结果一致；
- 固定阈值精确率/召回代理值绝对差不超过 0.5 个百分点；
- bbox/关键点 median 与 P95 增量不超过 0.5 px。

不满足时先定位预处理、坐标或后处理差异，不导出 ONNX。

### 4.3 FP16 ONNX

导出并检查：

```text
输入：images / FLOAT16 / [1,1,1280,1280]
输出：output0 / FLOAT16 / [1,31,34000]
```

在同一 462 张上做 FP16 ONNX evaluation。相对 PT 的首轮工程门禁：

- 精确率/召回代理值绝对下降不超过 0.5 个百分点；
- 匹配实例减少不超过 0.5%；
- bbox/关键点 median、P95 增量不超过 `max(1 px, 5%)`；
- 无类别从有效检测退化为零检测；
- 五个保护类别无系统性恶化。

FP16 与 PT 不等价时禁止开始 QDQ。

### 4.4 QDQ 量化

沿用已验证的最小结构：静态 QDQ、Conv 权重 QInt8、激活 QInt16、per-channel、Entropy、CPU calibration provider。该产物应描述为“权重 INT8、激活 QInt16”，不是严格全 INT8。

先用 42 张做耗时外推，再用完整 462 张标定；CPU 阶段设置 3 小时硬超时、16 CPU 和 64 GiB 内存上限。量化阶段不使用 GPU。

### 4.5 QDQ 快速评估门禁

在同一 462 张上比较 PT、FP16、QDQ。相对 PT 的首轮工程门禁：

- 精确率/召回代理值绝对下降不超过 1 个百分点；
- 匹配实例减少不超过 1%；
- bbox/关键点 median、P95 增量不超过 `max(2 px, 10%)`；
- 单类召回绝对下降不超过 3 个百分点；
- 不出现类别零检测、输出全零、NaN/Inf 或系统性背景误检；
- 五个保护类别必须单独通过人工复核。

这些是进入完整 test 回归的工程门禁，不等同于最终业务验收阈值。业务方可以在执行前收紧，但不能在看到量化结果后放宽。

### 4.6 完整 6,600 张回归

快速门禁通过后，在完整 test 上运行 FP16 和 QDQ 评估，复用当前 PT 的固定阈值、匹配和像素误差统计。最终报告必须包含总体、逐类、背景图、保护类别，以及 PT/FP16/QDQ 三方差异。完整回归未通过时不标记 `production_ready`。

## 5. cam2000 独立性能与语义验证

### 5.1 与量化输入分离

```text
量化标定：正式 net1280 Gray1 PNG -> [N,1,1280,1280]
cam2000：原始图 -> 2000×2000 -> 12-bit packed-u12 BIN
```

cam2000 每个 BIN 为 8,192,000 字节：每行 3,000 字节有效像素、stride 4,096 字节、行尾 1,096 字节补零、无文件头尾。462 个 BIN 约 3.52 GiB。它们不作为 ONNX 标定输入。

### 5.2 当前 CLI

`grayprep run cam2000` 仍未实现。当前可用命令是：

```text
grayprep dataset build-smoke
grayprep dataset verify-smoke
```

根据 `source_manifest.json` 将 calibration 的 462 张派生图映射回原始图，生成 `cam2000-selection.json`。不得把已 resize/padding 的 1280 PNG 再转换为 cam2000。

### 5.3 语义门禁

性能测试前先验证：

- 所有 BIN 均为 8,192,000 字节；
- 行尾补零和严格 decode 通过；
- 12-bit 到 8-bit、2×2 均值降采样、1000×1000 到 1280 padding 的实现明确；
- 从 cam2000 解码得到的网络输入与训练 `net1280` 输入做逐像素差异统计；
- 若两条预处理不等价，单独记录差异并停止宣称 FPGA 输入语义对齐。

### 5.4 性能实验

输出放在 `$SCRATCH/cam2000-benchmark`，记录：总 wall time、items/s、各阶段 p50/P95、CPU、峰值 RSS、读写字节、输出大小、失败数和 `.partial`。使用 1、8、16、32 workers；每种配置预热一次、正式运行三次，取中位数。

历史 4,200-item 组合流程在 `/data1`、32 workers、每 worker 1 个 OpenCV thread 时约 54.75 items/s；历史单进程候选约 2.44 frames/s。历史数据只用于发现明显回退，不代替本轮实测。

cam2000 性能和语义测试是独立结论，不阻塞 PT→FP16→QDQ 的软件量化验证；但进入 FPGA 输入回环前必须通过语义门禁。

## 6. 历史风险与停止条件

历史单通道 21 类任务 `20260909_191112_test_21_class_gray_input` 曾出现 PT F1 0.3418、量化 ONNX/输入回环 F1 为 0，以及 `generate_bin` 21 层 `KeyError: input`。该任务不是当前模型和数据，不能用于评价当前精度，但证明以下条件必须是硬门禁：

- PT 与 FP16/QDQ 不等价时停止；
- 输出有限、非全零只能作为结构检查，不能代表精度通过；
- 在修复 PT/ONNX 差异前不进入 FPGA/BIN；
- 历史三通道成功任务不能替代当前单通道验收。

其他停止条件：选择数量或 split 错误、group 约束不成立、图像不是 Gray1、ABI 错误、GPU 资源不安全、磁盘不足、cam2000 严格解码失败，或必须修改类别/shape/数据语义才能继续。

## 7. 执行顺序与预计时间

| 阶段 | 主要工作 | 预计耗时 |
|---|---|---:|
| 1 | 冻结身份、实现并测试选择工具 | 40–80 分钟 |
| 2 | 生成 calibration/evaluation 并检校 | 15–30 分钟 |
| 3 | 462 张双路径 PT 基线对齐 | 10–25 分钟 |
| 4 | FP16 导出与 462 张评估 | 20–45 分钟 |
| 5 | 42 张量化时间外推 | 10–20 分钟 |
| 6 | 462 张 CPU QDQ 标定 | 90–120 分钟 |
| 7 | 462 张 QDQ ONNX 评估 | 45–75 分钟 |
| 8 | 完整 6,600 张 FP16/QDQ 回归 | 以 462 实测外推，单独设超时 |
| 9 | cam2000 语义与性能实验 | 20–40 分钟 |
| 10 | 汇总、备份和结果评审 | 20–40 分钟 |

GPU 只用于 PT 和 FP16 导出；QDQ calibration、ONNX CPU evaluation 和 cam2000 不占 GPU。各阶段独立 checkpoint，不要求持续占用 GPU。
