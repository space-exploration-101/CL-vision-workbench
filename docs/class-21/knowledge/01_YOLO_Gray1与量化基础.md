# YOLO、Gray1 与量化基础

本文只保留理解本项目所需的知识。逐层网络图见[网络结构与 FPGA 适配说明](../architecture/Pose21_Gray1网络结构与FPGA适配说明.md)，通用推导见[视觉模型量化与 FPGA 入门](../../reference/VISION_MODEL_QUANTIZATION_FPGA_PRIMER.md)。

## 阅读前的几个概念

- **YOLO**：一种从图像直接预测目标类别和位置的神经网络；网络由多层数值运算构成。
- **权重**是训练学到的参数；**激活**是图片经过网络时产生的中间数值。
- **张量**是多维数值数组；`[B,C,H,W]` 依次表示图片数量、通道数、高、宽。RGB 有红绿蓝三通道，Gray1 只有一个灰度通道。
- **bbox** 是目标外接矩形框；**关键点**是目标上指定位置；Pose 表示同时预测位置点的任务。
- **PT** 是 PyTorch 模型文件；**ONNX** 是供推理工具执行的模型格式；INT8/FP16 分别指 8 位整数/16 位浮点数。
- **stride** 是采样间隔；**padding** 是补边或补齐；**NMS** 用来去掉同一目标的重复预测框。

## 1. 输入语义的演进

| 阶段 | 类别 | 张量 | 像素语义 |
|---|---:|---|---|
| 历史模型 | 2 | `[B,3,1280,1280]` | 只有 R 通道有效，G/B 为 0 |
| 过渡模型 | 21 | `[B,3,1280,1280]` | 仍是 R-only，用于先验证类别扩展 |
| 当前模型 | 21 | `[B,1,1280,1280]` | 真正 Gray1 |

R-only 不是普通 RGB。对 `(R,0,0)` 使用标准灰度公式会得到约 `0.299R`，改变亮度分布；正确迁移是显式取 R 通道，再作为单通道 Gray1。

## 2. 当前 Pose 输出如何组成

当前模型有四个检测尺度，stride 为 `8/16/32/64`。1280 输入产生：

```text
160^2 + 80^2 + 40^2 + 20^2 = 34,000 个候选
```

每个解码候选包含：

```text
4 bbox + 21 class + 2 keypoints x 3 = 31 个逻辑通道
```

因此 FP16 ONNX 输出为 `[1,31,34000]`。FPGA 目标布局把 31 个逻辑通道补齐为 32 个物理通道；`ch31` 只是 padding，不能参与分类、NMS 或关键点解析。

## 3. Gray1 改变了什么

单通道不仅减少输入数据量，还改变第一层卷积权重：从三通道形状变为 `[80,1,3,3]`。数据加载、模型预热、ONNX 输入、标定器、FPGA DMA 和第一层 lane 布局必须一起更新。只改图片格式或只改模型 YAML 都不构成完整迁移。

几何预处理也必须统一。当前 net1280 合同是：缩放到 `1000x1000`，四边各补 140 像素，再对 bbox 与关键点执行同一变换。训练、PT、ONNX 与软件回环必须复用该合同。

## 4. 量化的直觉

量化用有限整数格近似浮点数：

```text
real_value ~= scale * (integer_value - zero_point)
```

权重可按输出通道分别选 scale，激活通常依靠标定样本估计范围。范围过宽会浪费刻度，过窄会饱和；因此“模型可运行、输出非零”不等于精度可接受。

当前交付基线是 W8A16 weight-only：148 个卷积层的权重按输出通道量化为 QInt8，激活保持 FP16，没有激活 QDQ。QDQ 指量化再反量化的一对运算；旧激活 QInt16/QDQ 方案因精度下降被 9 月 20 日的 weight-only 方案替代。scale 是数值刻度，zero_point 是整数零位偏移。舍入、饱和和累加器位宽仍须与 FPGA 数值合同核对，软件精度不能自动外推到硬件。

## 5. PNG、缓存与 cam2000

- 正式真源：`1280x1280 uint8` Gray1 PNG，可视、可逐文件校验。
- 以下缓存是待实施优化；未压缩全量像素约 43.9 GiB；可派生 `.gray`、split mmap 或共享内存缓存减少重复解码。
- 缓存必须独立存放并绑定 PNG 哈希；失配即拒绝使用，不能覆盖正式数据集。
- cam2000 是相机/FPGA ABI：`2000x2000` packed-u12，每文件 8,192,000 bytes，行有效载荷 3,000 bytes、stride 4,096 bytes。它不能替代训练或量化输入。

## 6. 可复用教训

1. 模型合同必须同时固定任务、类别顺序、关键点、输入通道、输入语义、尺寸、stride 和输出布局。
2. 先验证 PT，再验证 FP16，再验证当前 weight-only ONNX，最后验证软件回环与实机；不要跨层归因。
3. 同一模型必须使用同一图片清单、阈值、NMS 和匹配方法比较。
4. 正向兼容不足以防错；加载端还要明确拒绝 2/21 类、三/单通道和类别顺序不匹配的包。
5. 运行名可能误导规模判断。当前运行名含 `m_50e`，实际模型 YAML 选择的是 `x` scale。
