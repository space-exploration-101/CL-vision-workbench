# 21 类目标数据与输入预处理

本文面向制作或复查数据的同事。预处理是把原图转成模型约定的尺寸与通道；标签记录正确类别、目标框（bbox）和关键点。train/val/test 分别用于学习、选择模型和最终测试；group 将同一来源的不同视角归组，避免同一场景跨集合造成结果偏乐观。manifest 是可复现的文件清单，哈希用于固定内容身份。

## 1. 当前旧版数据的转换合同

`pose21-gray1-1280-m-v1` 来自旧源数据 `Yolo_full`。源图主要是三通道 PNG
容器，但只在 R 通道保存灰度值。该版本的派生流程为：

```text
R-only 源图
-> 显式提取 R
-> resize 1000x1000
-> 四边 padding 140，填充值 0
-> 1280x1280 uint8 Gray1 PNG
-> bbox/关键点按相同几何变换重算
```

处理该版本时禁止使用 `BGR2GRAY`，禁止改变类别 ID、类别顺序或
`kpt_shape=[2,3]`。这些规则用于复现旧版数据，不代表后续新数据集仍以
`Yolo_full` 为源。

## 3. 后续数据集更新

旧版数据中，两个关键点在全部正样本里彼此重合，多数还位于 bbox 中心。
这不妨碍程序运行，但会削弱 Pose 指标的业务意义。因此后续应制作新数据集：

- 不再使用 `Yolo_full` 作为源数据；
- 更新目标的地标点及其标签质量；
- 保持上述 21 个目标类别、类别 ID 和顺序不变；
- 使用新的数据集 ID、来源记录、manifest 和验证报告，不覆盖旧版目录。

新数据集制作与当前旧版模型的训练、量化可以并行推进。每次训练和量化结果
必须绑定具体数据集 ID；新旧版本不得混合取样，也不能在未注明数据版本时直接
比较指标。

旧源数据已经完成历史保护：包含 `yolo_full` 的整个
`/data2/ai-i-chenshiwen/auto_landmark/Dataset` 已归档为快照
`auto-landmark-Dataset-20260922-161828`，状态为 `VERIFIED`，NAS 根目录为：


## 4. 当前旧版的量化数据选择

- calibration：从 train 选 462 张，21 类各 20 张正样本，加 42 张空标签；每 group 最多一张。
- quick evaluation：从 test 选 462 张，21 类各 18 张正样本，加 84 张空标签；尽量扩大 group 覆盖，每 group 最多两张。
- final evaluation：完整 6,600 张 test。

两份选择必须保存确定性 manifest，记录 seed、类别、group、相对路径和源文件身份。calibration 与 evaluation 不共享文件。

以下数量只适用于 `pose21-gray1-1280-m-v1`。新数据集发布后应根据其实际分布
重新制定 calibration 和 evaluation 选择清单，不能直接沿用旧清单。

## 5. 三种输入不能混用

| 用途 | 格式 | 规则 |
|---|---|---|
| 当前训练、PT、ONNX、量化 | net1280 Gray1 PNG | `[N,1,1280,1280]` |
| 相机/FPGA 输入 | cam2000 BIN | `2000x2000` packed-u12，8,192,000 bytes |
| 可选性能缓存 | raw `.gray`、mmap 或预加载 | 从 PNG 派生并绑定哈希 |

缓存仅是尚未实施的可重建优化。实施前要做逐像素 A/B、总耗时（wall time）与驻留内存（RSS）对比；执行须在具体任务授权内，也不能用它替代量化精度修复。

## 6. 生成与验收

大规模生成应写入同文件系统的 `.partial`，完成数量、shape、dtype、通道、
标签、group 隔离、抽样像素复算和哈希校验后再原子发布。源数据只读，失败
现场保留，不通过修改标签或源图绕过检查。新数据集还必须单独验收地标点语义
和标注质量，再进入对应版本的训练与量化结论。
