## 资料职责与更新顺序

- platform 保存平台事实和明确标记的 TODO 计划；模型、数据和接口说明留在 class-21。
- reference 解释通用概念、判断方法和验收层次；operations 提供日常平台运维的任务路线；rebuild 组织完整恢复与构建材料的选择和验收。三者不另维护资产或版本表。
- Agent topics 按问题提供小份事实入口；tasks 按操作提供必要输入、授权与验收。HANDOFF、CONTEXT、各级 README 和 rebuild 索引只保留短摘要、日期和链接。
- 新证据先核对模型、数据、环境、时间和授权，再更新本表指定来源；最后同步摘要。运行记录、正式附件、冻结脚本和原始清单不随摘要改写。

恢复快照里的 commit、镜像 ID 和模型哈希是历史资产身份，不是另一份“当前版本”。发现不一致时保留两端原文，登记[待核对项](OPEN_QUESTIONS.md)，未解决前不合并或提高状态。
