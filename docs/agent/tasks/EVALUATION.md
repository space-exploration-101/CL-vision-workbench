# 模型评估与 FPGA 对比

必要输入：具体评估目标、模型与数据身份、样本范围、阈值／容差及允许使用的资源。只加载相应报告章节与精确附件；验收分别报告软件功能、数值结果和真实硬件结论，不把计划门禁写成已完成。

先读 [MODEL_BASELINE](../topics/MODEL_BASELINE.md)；当前方案与评估口径详见[知识库 03](../../class-21/knowledge/03_训练评估量化与FPGA流程.md)。使用 GPU 前执行 [DIAGNOSTICS](DIAGNOSTICS.md) 的持续采样与 owner 检查，确认任务授权覆盖。

1. 固定数据/选择清单、PT/ONNX 哈希、代码、镜像 ID、provider 和参数；标签相同不代表镜像身份相同。
2. 默认沿用 `conf=0.25`、NMS IoU `0.7`、同类一对一 IoU≥0.5 匹配；关键点有效性和坐标口径以具体报告为准。不同数据或 mAP 定义不能直接横比。
3. 当前交付方案为 weight-only，旧激活 QDQ 失败结果不作为基线。按阶段选择 CPU/GPU，使用资源须在任务授权内。
4. 500 张批次使用当前编号路径；存在训练 group 重叠。执行验收、业务指标通过、独立泛化结论分别报告。
5. 逐层比较先核对固定图片、模型和 manifest；检查入口，再按依赖顺序比较 FPGA 回传。多输入、有效 lane、补零、小端 FP16、shape、scale 和算子顺序须对齐。
6. 保存首个偏离层、误差分布和事先确定的容差。T32 软件参考、相机 packed-u12、软件输入回环和 FPGA 实机推理分别验收。
7. 不覆盖已发布目录；新增阶段使用独立输出。500 张批次旧脚本是历史快照，不直接对已发布数据重跑。
