# 文档维护任务卡

适用：本机文档、导航、归档、历史内容压缩。无需访问 H200、GPU、NAS 或 work。

必要输入：本阶段目标、允许修改的文件范围及回滚基线。动态事实按[来源表](../../platform/SOURCES.md)只维护一处详细说明，其他入口保留短摘要、证据日期和链接；冲突登记[待核对项](../../platform/OPEN_QUESTIONS.md)，不得自行提高验收状态。

1. 读取相关 README、最近证据与现有链接；当前状态按模型、数据、镜像/提交身份和证据日期核对。
2. 人类文档在首次使用术语前解释含义；AGENTS 与上下文用短索引链接小主题。
3. 保留目录主干；失效的操作手册归档，仍支撑当前模型的报告和附件保持身份。
4. 历史压缩保留“原因 → 改动 → 验证 → 后续替代/未完成”及关键身份。原文可放可校验 ZIP，摘要不要重复过期状态表。
5. 变更前保留副本；被移动文件要更新活跃链接，受哈希保护的材料保留旧清单再更新新清单。
6. 校验 UTF-8、相对路径与页内锚点、当前/历史边界；不能因文档更新宣称远端已同步。

验收入口：`python -B tools/check_documentation_safe.py`。默认仅输出结果；如需保存，使用 `--report <已存在安全目录下的全新文件名>`，禁止覆盖已有报告。工具排除 work、临时/依赖目录，拒绝越界与 Windows reparse point/junction；不执行或导入业务脚本。原 check_documentation.py 保留为旧实现和 Markdown 解析辅助，不再作为直接执行入口。

维护校验工具时仅运行 `python -B tools/tests/test_check_documentation_safe.py` 的隔离测试，不批量发现或执行 tools/tests 中的业务测试。活跃链接直接检查，冻结例外仅采用已有精确映射并单独列出，不宣称原链接已修复。版本基线、最终快照及回滚见[最终交接](../../archive/2026-10-final-handoff/README.md)。完整实验附件与历史原文按对应清单独立验证。

严格隔离任务须先检查扫描边界，不沿 junction 或依赖链接访问外部目录；冻结包内旧引用按已记录迁移映射单列核对，不为了让默认检查器通过而重写证据。原始校验清单不覆盖，发布版本化新清单并保留旧版对应材料。验收同时检查事实职责、阅读路线和受保护文件身份。
