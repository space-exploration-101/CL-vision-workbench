# H200 平台恢复手册

整理：2026-10-18。恢复是把已保存的源码、软件环境、配置与数据重新组成可运行系统；有备份文件不等于已验证能恢复。当前总体仍为 `PARTIAL`。

## 1. 先判断丢失了什么

| 情况 | 先做什么 | 依据 |
|---|---|---|
| 主机重启，文件与镜像仍在 | 只读检查服务、任务、挂载和 GPU，再按授权启动 | [诊断](../agent/tasks/DIAGNOSTICS.md)、[服务操作](../agent/tasks/SERVICE.md) |
| 容器或镜像丢失 | 从 10.16 镜像集合导入对应资产，核对完整 ID | [镜像恢复步骤](../platform/01_NAS备份与环境恢复.md#64-按-1016-版恢复-docker-镜像) |
| 源码或数据丢失 | 在新目录恢复匹配源码、模型与独立数据归档 | [NAS 资产清单](../platform/01_NAS备份与环境恢复.md) |
| 系统重装或更换主机 | 核对主机依赖，完成隔离恢复；不要直接覆盖现用路径 | [重建指南](../../rebuild/REBUILD_GUIDE.md) |
| 无可用镜像或需要升级环境 | 先补齐构建材料，再构建候选镜像并回归 | [H200 构建条件](../platform/02_H200训练测试推理与量化运行环境.md#4-从-dockerfile-构建时要带哪些材料) |

H200 通过 `ssh H200` 直连。检查不自动授权中断任务、修改系统或写 NAS；已有授权范围内继续完成。

## 2. 选择匹配的恢复点

最近恢复基线沿用 10.16 镜像及独立数据归档证据。资产位置、完整身份和覆盖只在[平台 01](../platform/01_NAS备份与环境恢复.md)维护；本页解释如何选择恢复点，不另建资产清单。

每个资产先核对完成标记、文件清单、SHA-256 和格式，再导入到新目录或独立候选环境。使用完整镜像 ID 和固定源码提交，不以 latest、main 或相同文件名判断版本匹配。

10.18 最新 main 与原运行目录不同，见[源码身份](../agent/topics/REPOSITORIES.md)。恢复 10.16 快照时不能无验证地换成新 main。9 月 2 日系统快照只适用于 pre-Gray1 历史环境，见[历史备份证据](../archive/2026-09-migration/backup/BACKUP_STATUS.md)。

## 3. 主机与存储门禁

- 先检查系统架构、驱动、Docker/Compose、容器 GPU 支持和磁盘空间。H200 是共享服务器，全局修改需明确授权。
- NAS 使用前核对实际 CIFS 来源；10.16 记录为 autofs 触发，不能沿用“必须手工挂载”的旧结论。
- 凭据通过安全渠道恢复，不输出完整环境配置或写入文档、命令参数和日志。
- 数据先恢复到新的 `.partial` 目录，校验后同文件系统原子发布；不覆盖现有文件。
- GPU 验证只使用已分配设备，持续检查利用率、显存与进程归属。历史显存门槛不能代替任务峰值评估。

## 4. 分层验收

1. **资产完整**：镜像 ID、源码/补丁、模型和数据身份一致；宿主挂载与配置可解析。
2. **CPU 功能**：实际模块路径、Gray1 单图、输入形状、预处理和文件格式正确。
3. **GPU 功能**：获授权后检查实际设备、算子、训练/推理与资源峰值；小规模烟测只证明能运行。
4. **任务回归**：固定数据的 PT/ONNX、量化结构、BIN 和八阶段产物满足预设容差。
5. **服务**：health、ready、任务查询与结果下载通过。10.16 的 NVML/ready 503 是待复核项，不能只检查 health。
6. **恢复闭环**：在隔离环境记录版本、资源、时间、结果与剩余缺口，再判断整套恢复是否通过。真实 FPGA 精度另行验收。

系统备份不包含 `output_data`；旧 ZIP 不一定包含后加的逐层导出。逐项覆盖与缺口以[备份说明](../platform/01_NAS备份与环境恢复.md)为准，原始恢复文档可从[整理前文档包](../archive/2026-10-documentation-consolidation/README.md)追溯。
