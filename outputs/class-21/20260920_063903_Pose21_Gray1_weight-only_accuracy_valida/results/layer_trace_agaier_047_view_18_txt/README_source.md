# Pose21 Gray1 输入与输出文件说明

本目录包含单图 FPGA 调试使用的相机输入、网络入口输入及软件参考输出。模型为 21 类、单通道 Gray1、W8A16 weight-only；这些文件不代表 FPGA 实机已比对通过。

## 两张 PNG 的区别

两张 PNG 属于同名样本的不同输入版本，不是可直接去重的同一文件。本目录的 `agaier_047_view_18.png` 是 2000×2000 相机输入图；标定集里同名的 1280×1280 图片在本目录保存为 `source_image.png`。接手时应按以下关系选用：

```text
source_image.png          1280×1280 → network_input.bin → 软件参考最终输出
agaier_047_view_18.png    2000×2000 → agaier_047_view_18.bin → 相机前处理入口
```

两者尺寸、文件大小和 SHA-256 均不同，保留两份可以分别复核网络输入与相机输入。不要以 2000×2000 PNG 替换 `source_image.png`；后者还被上一级 `manifest.json` 的 `image.archived_file` 引用。

## 相机 BIN 的打包规则

灰度值按 `u12 = round(u8 × 4095 / 255)` 从 0～255 映射到 0～4095。相邻两个像素 P0、P1 打包为三个字节：

```text
byte0 = P0[7:0]
byte1 = (P1[3:0] << 4) | P0[11:8]
byte2 = P1[11:4]
```

按行从左到右、从上到下存储。每行 2000 个像素占 3000 字节，行尾补 1096 字节零，使行 stride 为 4096 字节；2000 行合计 8,192,000 字节。例如 `0xABC, 0x123` 打包为 `BC 3A 12`。

## 最终输出 TXT 的读取规则

2026-10-14 与下游确认：交付使用文件名带 `_T32_NC32.txt` 的新版，保留原始最终输出 BIN 的物理顺序及全部补零通道。原 BIN 为 `[34000,32]`，小端 FP16，ch0～30 有效，ch31 补零；每个候选位置连续写出 32 个通道，每个数独占一行，不转置为 `[C,N]`。

```text
第 1～32 行：位置 0 的 ch0～ch31，第 32 行为 0
第 33～64 行：位置 1 的 ch0～ch31，第 64 行为 0
依次排列，共 34000 组、1088000 行
```

以候选位置 n、通道 c 均从 0 开始计数，TXT 行号（从 1 开始）为 `32*n+c+1`。读取后先 reshape 为 `[34000,32]`；需要逻辑输出时，再取前 31 列、转置并增加 batch 维，得到 `[1,31,34000]`。ch31 仅供物理对齐，不能参与后处理。31 个有效通道由 4 个 bbox 分量、21 个类别分数和 6 个关键点分量组成；34000 = 160² + 80² + 40² + 20²。这些是解码后的密集候选输出，仍需阈值筛选及 NMS 等后处理才能得到最终检测结果。

新版 TXT 保留 FP16 原值的十进制精度，全部 1,088,000 个数值回读为 FP16 后与原 BIN 逐字节一致；每第 32 行的 34,000 个补零位置均验证为 `0`。不需要再次归一化。行数由 shape 决定，文本字节大小随数值、打印格式和换行方式变化。

新版 TXT 的 SHA-256：`e90361b0f3e1ed3000545790a59bc083d8d48785eba328683900464a15f067da`。旧版无 `_T32_NC32` 后缀的 TXT 按 `[31,34000]` 读取，不应与新版混用。

## 使用边界

`agaier_047_view_18.bin` 用于测试相机及前处理入口；`network_input.bin` 用于直接测试神经网络第一层；最终输出 TXT 用于与软件参考结果比较。相机 2000×2000 输入到网络 1280×1280 输入之间的缩放、归一化及布局转换，需要按照正式 FPGA 前处理合同独立核对，不能仅凭文件同名认定整条链路已验证。
