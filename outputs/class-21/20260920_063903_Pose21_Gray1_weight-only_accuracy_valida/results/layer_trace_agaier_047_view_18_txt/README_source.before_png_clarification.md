# Pose21 Gray1 输入与输出文件说明

本目录包含单图 FPGA 调试使用的相机输入、网络入口输入及软件参考输出。模型为 21 类、单通道 Gray1、W8A16 weight-only；这些文件不代表 FPGA 实机已比对通过。

## 文件来源与含义

| 文件 | 来源 | 含义与格式 |
| --- | --- | --- |
| `source_image.png` | 逐层导出选定的标定图片 `pose21_gray1_50e_cal462_v1/cali/agaier_047_view_18.png` 的原图副本 | 1280×1280、8-bit 单通道灰度 PNG；实际 ONNX 逐层推理使用此图。大小 733,394 bytes。 |
| `network_input.bin` | `source_image.png` 解码、resize 到 1280×1280、除以 255、转 FP16，再进行 T32 排列 | 网络第一层的直接输入，不是相机原始数据。逻辑 shape `[1,1,1280,1280]`，物理 shape `[1,1280,1280,32]`；小端 FP16，lane 0 有效，lane 1～31 补零。大小 104,857,600 bytes。 |

## 相机 BIN 的打包规则

灰度值按 `u12 = round(u8 × 4095 / 255)` 从 0～255 映射到 0～4095。相邻两个像素 P0、P1 打包为三个字节：

```text
byte0 = P0[7:0]
byte1 = (P1[3:0] << 4) | P0[11:8]
byte2 = P1[11:4]
```

按行从左到右、从上到下存储。每行 2000 个像素占 3000 字节，行尾补 1096 字节零，使行 stride 为 4096 字节；2000 行合计 8,192,000 字节。例如 `0xABC, 0x123` 打包为 `BC 3A 12`。

## 最终输出 TXT 的读取规则

原始最终输出 BIN 的物理 shape 为 `[34000,32]`，小端 FP16，ch0～30 有效，ch31 补零。TXT 已去掉 ch31，并改为逻辑通道顺序：

```text
第 1～34000 行：ch0 的全部候选位置
第 34001～68000 行：ch1 的全部候选位置
依次排列，最后 34000 行为 ch30
```

读取后 reshape 为 `[31,34000]`，增加 batch 维即可得到 `[1,31,34000]`。31 个有效通道由 4 个 bbox 分量、21 个类别分数和 6 个关键点分量组成；34000 = 160² + 80² + 40² + 20²。这些是解码后的密集候选输出，仍需阈值筛选及 NMS 等后处理才能得到最终检测结果。

TXT 保留 FP16 原值的十进制精度，全部数值回读为 FP16 后与原 BIN 对应值一致；不需要再次归一化。

## 使用边界

`agaier_047_view_18.bin` 用于测试相机及前处理入口；`network_input.bin` 用于直接测试神经网络第一层；最终输出 TXT 用于与软件参考结果比较。相机 2000×2000 输入到网络 1280×1280 输入之间的缩放、归一化及布局转换，需要按照正式 FPGA 前处理合同独立核对，不能仅凭文件同名认定整条链路已验证。
